## 12. Codex-ревью этапа 16

Все 9 замечаний исправлены, на каждое исправление кода добавлен тест.

1. (High) Восстановление блокировалось на повреждённой базе → текущая база и её `-wal`/`-shm`/`-journal` сохраняются сырым `shutil.copy2` в `.before-restore-<время>`; сбой копирования не мешает восстановлению. Тест: test_restore_over_corrupted_db_keeps_raw_copy.
2. (High) Остановка оставляла задачи → listener и опрос бота — отдельные задачи под `asyncio.wait(FIRST_COMPLETED)`, упавшая ветка останавливает вторую и пробрасывает исключение; в `finally` отменяются и ожидаются (10 с) все задачи, включая flush/cleanup, затем alert остановки (5 с) и закрытие клиентов/БД. Тесты: test_one_branch_failing_cancels_the_other_and_flush_tasks, test_cancellation_sends_shutdown_alert_before_bot_close_and_returns_0.
3. (Medium) Healthcheck не замечал полный отказ каналов → `last_success_poll_at` (только цикл без полного провала) пишется в heartbeat, `check` использует его; `last_poll_at` остался для интерфейса бота. Тест: test_all_failing_cycles_make_healthcheck_unhealthy_until_a_success.
4. (Medium) Ротация бэкапов по имени могла удалить свежий файл после смены часов → новый файл не удаляется, остальные сортируются по mtime, остаётся keep-1. Тест: test_rotation_never_deletes_the_new_file_after_clock_change.
5. (Medium) Сбой копии сессии выглядел как успех → `last_error` = «сессия не сохранена: ...» и alert `backup_failed`, копия БД сохраняется (экран «Бэкапы» показывает last_error). Тест: test_session_copy_failure_is_reported.
6. (Medium) Восстановление сессии не трогало её sidecar-файлы → `-wal`/`-shm`/`-journal` сохраняются сырой копией и удаляются перед заменой. Тест: test_restore_session_saves_and_clears_sidecars.
7. (Medium) Планировщик бэкапов читал часовой пояс один раз перед долгим сном → сон кусками до 60 с, цель пересчитывается по живым часу и поясу, запуск при достижении времени, если для местной даты бэкапа ещё не было. Тесты: test_run_loop_applies_timezone_change_and_never_double_runs, test_run_loop_does_not_back_up_on_start_after_the_hour.
8. (Medium) Повреждённая БД при `db.init()` не давала alert → при `DatabaseError` экстренный alert напрямую через короткоживущего Bot(NOTIFY_BOT_TOKEN) (`send_emergency_alert`, маркер `data/integrity_alert.json`, не чаще раза в 6 ч, не бросает исключений), код выхода 2. Тесты: test_emergency_alert_is_rate_limited_by_marker, test_emergency_alert_send_failure_is_swallowed_and_not_marked, test_corrupted_db_sends_emergency_alert_and_returns_2.
9. (Low) DEPLOY.md: после `sudo git clone` каталог принадлежал root → добавлен `sudo chown -R "$USER":"$USER"`, `sudo chmod 700 data`; те же правки в QUICK_START.md и README.

В CLAUDE.md добавлено правило: фоновые планировщики перечитывают живые настройки при каждом пробуждении, при остановке отменяются и ожидаются все задачи.
